# RoboShop on AWS: Terraform + Ansible + load balancers

This deploys the [roboshop-monolith](https://github.com/raghudevopsb90/roboshop-monolith) app in a production-style layout:

- **Terraform** creates the infrastructure: VPC, subnets, NAT gateways, security groups, EC2 instances, two ALBs, RDS, Route53 records, the ACM certificate and an SSM parameter.
- **Ansible** configures the servers: Nginx and the Spring Boot app.

The source is one monolith (a single WAR), so redundancy is per tier. Each tier runs on at least 2 nodes in 2 AZs behind its own load balancer.

## Architecture

```
                        Internet
                           │
          roboshop.example.com  (public Route53 → ACM TLS)
                           │
                ┌──────────▼───────────┐   public subnets (AZ-a, AZ-b)
                │  Public ALB  :80→443 │   + bastion (SSH from admin IP only)
                └──────────┬───────────┘   + NAT gateways
           ┌───────────────┴───────────────┐
     ┌─────▼─────┐                   ┌─────▼─────┐   private subnets
     │  web-1    │                   │  web-2    │   Nginx :80
     │  (AZ-a)   │                   │  (AZ-b)   │   static css/js/images
     └─────┬─────┘                   └─────┬─────┘
           └───────────────┬───────────────┘
            app.roboshop.internal  (private Route53)
                ┌──────────▼───────────┐
                │ Internal ALB :80     │   sticky sessions (lb_cookie)
                └──────────┬───────────┘
           ┌───────────────┴───────────────┐
     ┌─────▼─────┐                   ┌─────▼─────┐   private subnets
     │  app-1    │                   │  app-2    │   Spring Boot :8080
     └─────┬─────┘                   └─────┬─────┘
           └───────────────┬───────────────┘
           mysql.roboshop.internal  (private Route53 CNAME)
                ┌──────────▼───────────┐   database subnets (no internet)
                │ RDS MySQL 8.4        │   Multi-AZ, encrypted,
                │ primary + standby    │   7-day backups
                └──────────────────────┘
```

### DNS

| Name | Zone | Points to | Used by |
|---|---|---|---|
| `roboshop.<domain>` | public | Public ALB (alias) | Customers, over HTTPS |
| `bastion.<domain>` | public | Bastion EIP | Admins, over SSH |
| `app.roboshop.internal` | private | Internal ALB (alias) | Nginx `proxy_pass` |
| `mysql.roboshop.internal` | private | RDS endpoint (CNAME) | App JDBC URL |
| `web-N` / `app-N.roboshop.internal` | private | Instance IPs | Troubleshooting |

### Security groups (each tier only accepts traffic from the tier in front of it)

`0.0.0.0/0 → ALB :80/443 → web :80 → internal ALB :80 → app :8080 → RDS :3306`. SSH to web and app is allowed only from the bastion.

## Prerequisites

1. An AWS account and credentials (`aws configure`).
2. A **public Route53 hosted zone** for a domain you own (`domain_name`).
3. Terraform 1.6 or later.
4. Ansible 2.15 or later with `boto3`. **Ansible does not run on Windows**, so use WSL (Ubuntu):
   ```bash
   sudo apt install -y python3-pip && pip install ansible boto3 botocore
   ```
5. An SSH key pair:
   ```bash
   ssh-keygen -t ed25519 -f ~/.ssh/roboshop -N ""
   ```

## Deploy

```bash
# 1. Infrastructure (takes about 15 min; RDS Multi-AZ is the slowest part)
cd terraform
cp terraform.tfvars.example terraform.tfvars   # edit domain_name + admin_cidr
terraform init
terraform apply                                # also writes ../ansible/inventory/hosts.ini

# 2. Configuration
cd ../ansible
ansible-galaxy collection install -r requirements.yml
ansible all -m ping                            # goes through the bastion
ansible-playbook site.yml

# 3. Open the app
terraform -chdir=../terraform output app_url
```

### Rolling release of a new version

```bash
ansible-playbook site.yml -e roboshop_redeploy=true
```

`serial: 1` updates one node at a time. The ALB health checks remove the node being updated from the pool while the other node keeps serving.

### Tear down

Set `db_deletion_protection = false`, run `terraform apply`, then run `terraform destroy`.

## Production choices

| Concern | How it's handled |
|---|---|
| High availability | 2 or more nodes per tier across 2 AZs, NAT gateway per AZ, RDS Multi-AZ |
| TLS | ACM certificate on the public ALB, HTTP redirects to HTTPS (301), TLS 1.2/1.3 policy |
| Secrets | DB password generated by Terraform and stored in SSM SecureString. Ansible looks it up at runtime and writes it to a root-only `0600` env file. It is not stored in git or in the systemd unit. |
| Network isolation | Only the ALB and bastion are public. RDS sits in subnets with no internet route. |
| Hardening | IMDSv2 only, encrypted EBS and RDS, SELinux enforcing (`httpd_can_network_connect`), `server_tokens off`, systemd `NoNewPrivileges` |
| Health checks | Public ALB checks `/nginx-health`. Internal ALB checks the app's `/health`. Ansible also checks both before moving to the next node. |
| ALB IP changes | Nginx uses the VPC resolver plus a variable in `proxy_pass`, so it re-resolves the internal ALB name |
| Sessions | The app keeps the cart and login in the HTTP session, so the app target group uses sticky cookies |

## Known caveats / next steps

- **Health path is not verified.** The README says the app serves `curl localhost:8080/health`, but I haven't checked this against the source. If that path fails, set `app_health_check_path` (Terraform) and `app_health_path` (Ansible) to `/`.
- **WAR path is not verified.** The README's unit uses `target/roboshop.war`. The playbook fails with a clear message if Maven produces a different file name. Fix `app_war_path` in that case.
- **Schema init:** the app runs `spring.sql.init.mode=always` on every start. If its seed SQL is not idempotent, restarts may create duplicate rows or fail. `serial: 1` at least prevents two nodes from initialising at the same moment.
- **Build on every node:** each app node runs Maven itself. A better approach is to build the WAR once in CI, store it in S3 or a registry, and have Ansible only download it.
- **Auto Scaling:** instances are fixed (`web_count`/`app_count`). The next step is a Launch Template plus an ASG per tier, using a pre-baked AMI (Packer + these same Ansible roles) or the `aws_ec2` dynamic inventory.
- **Terraform state** holds the DB password. Enable the S3 backend in `versions.tf` (encrypted, with locking).
- The JDBC URL keeps the README's `useSSL=false`. For stricter setups, set `require_secure_transport` on RDS and use `sslMode=REQUIRED`.
